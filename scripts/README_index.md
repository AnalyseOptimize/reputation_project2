# Данные для компонент индекса

```sh
.venv/bin/python scripts/build_index_data.py
```

В корне проекта создаются две таблицы по 110 компаний:

- `index_data.csv` — компоненты по всем людям своего источника;
- `index_data_ceo.csv` — компоненты только по CEO своего источника.

Ровно шесть колонок: `ticker`, `media_score`, `awards_score`,
`expertise_score`, `face_score`, `communication_score`. Все компоненты имеют
шкалу 0–100. Общий индекс как взвешенная сумма компонент не рассчитывается.
Исходные признаки, веса и количества наблюдений сохраняются отдельно в аудите.

## Независимость компонент и CEO

Каждая персональная компонента рассчитывается и усредняется внутри своего
источника. Между компонентами объединяются только готовые средние по `ticker`.
Сопоставления ФИО между медиа, наградами, фото и образованием нет.
Если CEO присутствует в образовании, но отсутствует в медиа, он участвует
только в образовательной компоненте; её доступность не зависит от медиа.

Для медиа, наград и фото CEO определяется по `Position` и компании в том же
файле. Поддерживаются CEO, chief executive officer, генеральный директор,
председатель правления и главный исполнительный директор. Заместители,
советники и явно указанные руководители других компаний исключаются.
Если работодатель указан в должности, он должен соответствовать компании
строки или её явному алиасу. Должности используются в том виде, в котором
они присутствуют в источнике: историческая проверка состава на 2024 год
между источниками не проводится.

Для образования CEO определяется разделом `ceo` в собственных JSON.
Рассчитанный CSV связывается с этими JSON точным ключом `(ticker, name)`;
это связь данных внутри одной компоненты. Несоответствие состава вызывает
ошибку с просьбой пересоздать образовательный CSV.

Повторные должности одного человека схлопываются только внутри своего файла:
первое непустое значение каждого показателя, CEO — наличие соответствующей
роли хотя бы в одной записи. Три явных алиаса имён устраняют локальные дубли.
Безымянные строки не считаются людьми. Тикеры `TCSG` и `YNDX` приводятся к
`T` и `YDEX`. Ошибочный `HEAD` у Henderson исправляется на `HNFG` по названию
компании. Медиаупоминания человека из другой компании не переносятся.

## Нормировка и агрегация

Все персональные показатели нормируются **до усреднения**. Границы фиксированы
и одинаковы для полной и CEO-выборок; выборочные минимум, максимум и
процентили не используются. Значения за границами обрезаются.

| Компонента | Персональный балл до усреднения |
| --- | --- |
| `media_score` | `100 × log1p(clip(yandex_count, 0, 100000)) / log1p(100000)`; верхняя граница искусственная |
| `awards_score` | Сумма `N=1`, `W=2` за 2015–2024; `100 × log1p(сумма) / log1p(20)`; максимум 20 теоретический |
| `face_score` | `100 × (clip(facial_trust_appearance_proxy, -3, 3) + 3) / 6`; обе границы искусственные |
| `expertise_score` | Средние нормированных образовательных признаков, взвешенные методом CRITIC; подробности ниже |
| `communication_score` | `100 × (Тональность + 1) / 2`; теоретические границы −1 и 1 |

Порог медиа 100000 и диапазон визуального показателя [−3, 3] — явные
настройки шкал, а не оценки по текущим данным. Их можно изменить аргументами
`--media-upper`, `--face-lower`, `--face-upper`.

Среднее каждой компоненты использует только её наблюдаемые значения.
Нет значения или подходящего CEO — пустая ячейка, а не ноль. Для наград
пустая годовая отметка в существующей строке означает отсутствие номинации
и даёт 0; отсутствие самого человека не создаёт нулевого наблюдения.
Коммуникация уже относится к компании и одинакова в обеих таблицах.
При наличии `positive` и `negative` вместо категории используется их разность.

## Образование и CRITIC

Используются признаки из `education/eduction_processed.csv`, рассчитанные
`scripts/process_education.py`. Подготовка общая с ноутбуком
`notebooks/education_index_experiments.ipynb` и реализована в
`utils/education_weighting.py`.

Из признаков формируется 21 критерий. Наивысшая степень преобразуется в
три накопительных индикатора: бакалавр или выше, магистр или выше, научная
степень. MBA/EMBA учитывается отдельно. Служебные флаги неизвестного уровня
образования и неполноты количества публикаций/патентов не получают веса.

Бинарные критерии имеют теоретические границы [0, 1]. Для количественных
критериев нижняя граница 0, верхние границы искусственные:

| Критерий | Верхняя граница |
| --- | ---: |
| Публикации | 100 |
| Патенты | 20 |
| Исследовательский опыт, годы | 40 |
| Опыт в sector / industry / industry_group, годы | 60 для каждого |
| Общий профессиональный опыт, годы | 100 |
| Опыт в текущей компании, годы | 50 |

Каждый персональный критерий обрезается по своим границам и линейно
нормируется в [0, 1], затем усредняется по людям компании. Логарифмирование
образовательных критериев в основном расчёте не применяется.
Пропуски персональных значений пропускаются при усреднении. Если целиком
отсутствует критерий компании, расчёт останавливается, без заполнения нулём.

На полученной матрице компаний CRITIC рассчитывает
`C_j = std_j × sum_k(1 − corr_jk)` и `w_j = C_j / sum(C)`;
используется корреляция Пирсона со знаком. Постоянные критерии исключаются
и получают нулевой вес. При отсутствии различий/конфликта расчёт выдаёт ошибку.
Образовательная компонента: `100 × sum_j(w_j × mean_normalized_j)`.

Веса оцениваются отдельно для всех менеджеров и для CEO, как в ноутбуке.
В текущих данных это 110 и 105 компаний соответственно. У BANEP, CBOM,
CHMK, LKOH и OZON `ceo=null` в образовании: их CEO-образование остаётся
пустым, но остальные компоненты могут быть доступны из своих источников.
Бутстрап в сборке не нужен: используется точечная оценка CRITIC.

## Запуск и проверки

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/requirements_index.txt
.venv/bin/python scripts/process_education.py
.venv/bin/python scripts/build_index_data.py
.venv/bin/python -m unittest discover -s tests -v
```

Дополнительные аргументы: `--root`, `--education-file`, `--output-dir`,
`--audit-dir`. Исходные файлы не изменяются. CSV сохраняются в UTF-8 с BOM,
без округления баллов. Все компании из объединения источников сохраняются.

Тесты проверяют фиксированную нормировку, пропуски, независимые знаменатели,
отбор CEO по своему источнику и совпадение CRITIC со спецификацией ноутбука.
Сквозной тест использует полностью разные имена во всех компонентах,
проверяет CEO с образованием без медиа и обратный случай; переименование
медийных записей не изменяет ни одной компоненты.

## Описательная статистика и устойчивость индекса

`notebooks/index_eda.ipynb` читает две готовые таблицы и исследует компоненты,
равномерно взвешенный итоговый индекс и CRITIC по пяти компонентам.
Зависимости ноутбука: `scripts/requirements_education_experiments.txt`.
Достаточно выполнить все ячейки по порядку.

Основные рейтинги строятся по полным наблюдениям: сейчас 64 компании для всех
менеджеров и 28 для CEO. Шкала уже фиксирована в сборке; перед взвешиванием
компоненты только делятся на 100. Для описательной статистики доступны также
остальные компании с наблюдаемыми отдельными компонентами.

Устойчивость измеряется корреляциями Spearman и Kendall τ-b, сдвигами рангов
и Jaccard топ-10. Проверяются 3000 случайных наборов весов и сетка изменения
каждого веса. CRITIC бутстрапируется 2000 раз отдельно для каждой выборки:
в каждом повторе выбирается с возвращением столько строк компаний, сколько
в исходной полной выборке; рейтинг оценивается на её исходном составе.
Это бутстрап внешних весов при фиксированных компонентах и образовательных весах.

Ноутбук сохраняет таблицы, веса, интервалы, аудит повторений и параметры
в `results/index_eda/`; графики — в `figs/index_eda_*.pdf`.
Итоговые индексы находятся в `all_managers_indices.csv` и `ceo_indices.csv`
в каталоге результатов. Все 110 тикеров сохранены; без полного набора компонент
индекс остаётся пустым. Краткие выводы автоматически формируются в `findings.md`.

## Регрессии на финансовые результаты

`notebooks/index_regression.ipynb` реплицирует финансовую часть
`notebooks/index_0_finance.ipynb` для всех менеджеров и CEO. Зависимости:

```sh
.venv/bin/python -m pip install -r scripts/requirements_index_regression.txt
```

Входы: `Companies_MOEXBMI_2024_2025.xlsx`, `index_data.csv`, `index_data_ceo.csv`,
а также готовые общие индексы и веса из `results/index_eda/`. Сначала выполните
EDA-ноутбук, затем все ячейки регрессионного. Соответствие EDA текущим компонентам
проверяется; устаревшие результаты не используются молча.

Исходы — ROA и доходность акций 2025. Рассчитываются M1–M5, C2024 и W2025:
образование отдельно, общие индексы с равными весами/CRITIC и компоненты совместно.
Есть отдельные M3-регрессии каждой компоненты, BH-коррекция p-value, сравнение
моделей на одинаковых компаниях, HC3 и условный LOOCV при фиксированных индексах.
В приложении CatBoost–SHAP внешние веса обучаются заново в каждом LOOCV-повторе.

В `results/index_regression/` сохраняются основные таблицы `primary_M3_fdr.csv`,
`individual_components_fdr.csv`, `model_comparison_common_sample.csv`, полные
коэффициенты `all_coefficients.csv`, составы выборок, диагностика, краткие выводы
и манифест входных файлов. Графики — `figs/index_regression_*.pdf`.

В данных есть постоянные компоненты и компоненты, отличающиеся только у одной
компании. Такие случаи явно отражены в `joint_M3_component_variation.csv` и
`leverage_one_observations.csv`; неопределённые ошибки HC3/LOOCV оставлены пустыми.
Модели с недостаточным числом наблюдений перечислены в `all_model_diagnostics.csv`.
При оценке HC3 используются t-критические значения, как в основной ячейке исходника.
